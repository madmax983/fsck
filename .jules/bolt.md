**[In-Place String Mutations vs Re-allocations]**
**Learning:** `EmotionalBleed::inject_emotion` and its helper functions were previously taking a `content: &str` and allocating a new `String` using `String::with_capacity` to build up the result, returning a fresh `String` on every call. This causes unnecessary intermediate heap allocations.
**Action:** Changed the signature to take a `content: &mut String` to allow the functions to modify the string in-place or replace its contents via dereferencing (`*content = result;`) while reusing the passed-in buffer where possible, eliminating the intermediate string allocation in `apply_emotional_bleed`. Note that sometimes you still need a temporary buffer if you are replacing the entire string content (like when adding newlines or interspersing characters), but it avoids allocating a *new* return string on top of the old one, and it aligns with taking a `&mut String` for things like `inject_dynamic_file_content`.
